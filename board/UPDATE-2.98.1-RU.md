# 2.98.1 — «мост ждёт скетч»: скетч больше не зависит от драйверов Zephyr

## Причина (наиболее вероятная)
Симптом «мост ждёт скетч» без ошибок в Python держится с 2.97.0 — версии, где PCM-голос на D9
стал вызывать драйверы Zephyr прямо из скетча (`DEVICE_DT_GET`, `pwm_set_cycles`, `counter_*`,
`irq_lock`). Скетч UNO Q грузится как llext-модуль: сборка с такими символами проходит, но при
загрузке на MCU они могут не разрешиться — тогда скетч молча не стартует, `Bridge.begin()` не
выполняется, Python ничего не слышит. (Тот же класс ошибок, что и TLS-символы в 2.97.3, но
виден только при загрузке.)

## Что сделано
1. `sketch/pwm_voice.h`: драйверный код PCM компилируется только с `-DNEURO_PCM_ENABLE`.
   По умолчанию RPC `pcm_*` отвечают `error:D9_PWM_or_TIM16_unavailable` (Python это уже умеет —
   речь идёт через другой выход), а в скетче нет ссылок на pwm/counter/irq/device.
2. Кольцевой буфер PCM в этом режиме занимает 16 байт вместо 32 КБ (BSS скетча ~85 КБ → ~52 КБ).
3. Версия 2.98.1 (Python, скетч `on_sver`, app.yaml). Протокол и память не менялись.

## Установка
App Lab: Stop → Build → Start (лучше полный ZIP либо замена `sketch/` целиком вместе с `pwm_voice.h`
и `pcm_ring.h`). Ожидается в журнале «СКЕТЧ запуск: шаг 1 — мост поднят», в диагностике `sver` 2.98.1.

## Если всё равно «ждёт скетч»
Пришлите вывод сборки/заливки (`neuro12_start.log`, `arduino-app-cli app logs`) и `journalctl -u arduino-router`.
Без реальной платы и Arduino toolchain сборка здесь не выполнялась; проверены синтаксис скетча на
хосте с заглушками, отсутствие неразрешённых символов Zephyr в объекте и 8 наборов тестов.
PCM на D9 в этой версии отключён (был экспериментальным).
