# Запуск neuro_12 через командную строку (без App Lab) и автозапуск

App Lab — это просто графическая оболочка над официальной утилитой
**`arduino-app-cli`**, которая УЖЕ установлена на самой плате UNO Q (Debian).
Ей можно собирать, прошивать и запускать приложение целиком (и скетч на MCU,
и Python на MPU) — без App Lab и без кнопки Run.

## Что нужно один раз

1. Плата настроена (App Lab использовался хотя бы раз при настройке): создан
   пользователь **arduino** с паролем, включён SSH-сервер, плата в Wi-Fi.
2. Ты знаешь IP платы. Если не знаешь — посмотри в роутере или зайди в
   терминал App Lab (кнопка `>_`) и выполни `ip addr show` (смотри `wlan0`).

## Шаг 1. Скопировать приложение на плату (с компьютера)

```bash
# neuro_12/ — распакованная папка приложения (app.yaml, python/, sketch/, assets/)
ssh arduino@<IP> "mkdir -p ~/ArduinoApps"
scp -r neuro_12 arduino@<IP>:ArduinoApps/
```

Или одной командой (есть готовый скрипт в этой папке):

```bash
bash push_and_run.sh arduino@<IP> /путь/к/neuro_12
```

## Шаг 2. Запустить (на плате, по SSH)

```bash
ssh arduino@<IP>
arduino-app-cli app start ~/ArduinoApps/neuro_12
```

`app start` делает ВСЁ то же, что кнопка Run: собирает и прошивает скетч на
MCU и запускает Python-часть на MPU. Первый старт может идти несколько минут
(сборка скетча, установка библиотек) — это нормально. Предупреждения про EOL
можно игнорировать.

**Важно:** Python печатает не в консоль, а в лог. Смотреть так:

```bash
arduino-app-cli app logs ~/ArduinoApps/neuro_12
```

## Шаг 3. Открыть интерфейс

Браузер: **http://<IP-платы>:7000** (кирпич web_ui слушает порт 7000).
Быстрая проверка живости из терминала платы:

```bash
curl -m 5 http://127.0.0.1:7000/api/state
```

## Остановить

```bash
arduino-app-cli app stop ~/ArduinoApps/neuro_12
```

## Сторож: автоперезапуск, если плата отключилась от порта (v2.62)

Если приложение neuro_12 падает или зависает, облако пишет «ошибка подключения
платы» (WinError 10061). Сторож живёт **на самой плате** и сам поднимает
приложение — компьютер для этого не нужен:

- каждые 15 с проверяет `http://127.0.0.1:7000/api/alive`;
- 3 неудачи подряд (≈45 с) — порт не отвечает, **или** приложение сообщает,
  что поток связи с облаком / основной цикл завис больше 10 мин — перезапуск:
  `arduino-app-cli app stop` + `app start` (как кнопка Run: скетч + Python);
- ждёт, пока порт ответит (до 5 мин); не поднялось — повтор через 1, 2, 5, 10 мин;
- история перезапусков — в `neuro12_watchdog.json` в папке приложения;
  приложение отправляет её облаку, в журнале облака видно
  «плата сообщила о прошлом падении: перезапущено сторожем (всего N): причина».

**Поставить с Windows в один шаг:** запусти `install_watchdog.bat` из этой папки,
введи IP платы и пароль пользователя arduino (дважды: для копирования и для sudo).

Или по SSH на плате: `sudo bash install_autostart.sh watchdog`.

Приостановить сторожа (например, пока правишь приложение в App Lab), не
останавливая службу: `touch ~/ArduinoApps/neuro_12/.watchdog_pause`; удалить
файл — слежение продолжится. Совсем выключить: `sudo systemctl disable --now neuro12`.

Сторож не мешает кнопке Run в App Lab: пока приложение отвечает, он ничего не
делает. Но если ты **сам остановишь** приложение в App Lab, сторож через
~45 с запустит его снова — для остановки используй паузу или `systemctl stop`.

## Автозапуск при включении платы (systemd)

`arduino-app-cli app start` НЕ переживает перезагрузку сам. Надёжный способ —
systemd-юнит прямо на плате. В этой папке есть установщик: он сам найдёт пути,
создаст юнит и включит его.

Вариант **watchdog** (рекомендуется): юнит не просто стартует приложение при
загрузке, а следит за ним — если веб-интерфейс :7000 перестал отвечать,
перезапускает через `app start`. Само приложение после сбоя платы поднимется
автоматически.

Вариант **simple**: одна попытка `app start` при загрузке, без слежения.

Установка НА ПЛАТЕ (по SSH):

```bash
cd ~/ArduinoApps/neuro_12/deploy_cli
sudo bash install_autostart.sh watchdog    # или: sudo bash install_autostart.sh simple
sudo systemctl start neuro12               # запустить прямо сейчас (не дожидаясь перезагрузки)
```

Управление и диагностика:

```bash
systemctl status neuro12          # состояние юнита
journalctl -u neuro12 -f          # живые логи watchdog'а
arduino-app-cli app logs ~/ArduinoApps/neuro_12   # логи самого приложения
sudo systemctl stop neuro12       # остановить (watchdog больше не перезапустит)
sudo systemctl disable --now neuro12   # совсем убрать автозапуск
```

## Нельзя запускать одно и то же дважды

Выбери ОДИН способ запуска:

- либо кнопка **Run** в App Lab (и его автозапуск, если ты его включал),
- либо CLI: `arduino-app-cli app start` + systemd-юнит из этой папки.

Если запустить оба сразу — второй упрётся в занятый порт 7000 и мост MCU.
Если меняешь способ: сначала `arduino-app-cli app stop ~/ArduinoApps/neuro_12`
или `sudo systemctl stop neuro12`.

Кстати: копия приложения, которую App Lab импортировал сам, лежит где-то ещё
на плате. Найти её можно так: `find / -name app.yaml -path "*neuro*" 2>/dev/null`
— её тоже можно стартовать через `arduino-app-cli app start <тот путь>`.

## Файлы этой папки

| Файл | Что делает |
|---|---|
| `push_and_run.sh` | С ПК: копирует приложение на плату по scp и запускает |
| `install_autostart.sh` | НА плате (sudo): ставит systemd-юнит автозапуска |
| `neuro12_watchdog.sh` | Сторож: перезапускает приложение, если порт 7000 не отвечает или оно зависло |
| `install_watchdog.bat` | С Windows: копирует сторожа на плату и ставит службу (ssh/scp) |

## Если что-то не так

- `command -v arduino-app-cli` — пусто? Обнови систему платы через App Lab
  (CLI ставится вместе с системным обновлением Arduino OS).
- Юнит стартует, но приложения нет: смотри `journalctl -u neuro12 -b` и
  `arduino-app-cli app logs`. Первый старт после перезагрузки требует Wi-Fi —
  watchdog по умолчанию ждёт 90 с и при неудаче пробует снова.
- Порт занят: `sudo fuser -k 7000/tcp` убьёт чужой процесс на :7000.
