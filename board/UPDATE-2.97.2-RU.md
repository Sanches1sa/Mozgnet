# 2.97.2 — устранение возможной блокировки запуска Bridge

Симптом: Python работает, а статус остаётся «мост ждёт скетч», ошибок может не быть.

В setup() до регистрации RPC находился Monitor.begin(). В исходниках Arduino_RouterBridge этот вызов синхронно обращается к mon/connected и запрашивает версию Router. Поэтому доступность Monitor могла задержать запуск команд приложения. Monitor.begin и дублирование журнала в Monitor удалены. Журнал скетча сохраняется через уведомления on_log.

Теперь сразу после Bridge.begin регистрируются RPC, отправляются on_boot(1) и on_sver с версией 2.97.2; потом запускаются I2C, UART, EEPROM и остальные подсистемы. Сам Bridge.begin по-прежнему нуждается в работающем системном Router: эта правка не заменяет сервис Router и не гарантирует устранение любой причины отсутствия скетча.

PWM D9 сохранён и не инициализируется во время setup. Python не отправляет PCM, пока нет свежего ответа скетча. Монтаж усилителя, eSpeak и ограничения TIM16 описаны в UPDATE-2.97-RU.md.

## Установка

1. Сохраните память/конфигурацию и остановите приложение в App Lab.
2. Обновите приложение полным ZIP 2.97.2 либо замените в существующем приложении python/main.py и sketch/sketch.ino файлами из него. Новые PWM-заголовки предыдущей версии должны оставаться рядом со sketch.ino. При полном импорте новый каталог сам не получает старую память.
3. Нажмите Run и дождитесь сборки, загрузки MCU и запуска Python. Изменение только Python эту проблему не исправляет: нужен обновлённый скетч.
4. В журнале Python ожидаются «СКЕТЧ запуск: шаг 1 — мост поднят», затем этапы 2, 3, 4, 9. Версия скетча в диагностике — 2.97.2. Если видна прежняя версия, новый MCU-код не загружен.
5. Если плата всё ещё не отвечает, остановите приложение и выполните один обычный перезапуск UNO Q, затем Run. Если и после этого нет шага 1, причина может быть до регистрации RPC: запуск MCU, загрузка скетча, системный Router или Bridge.begin. Тогда нужен журнал Sketch/системного Router, даже если журнал Python не содержит ошибок. Если шаг 1 появился, но до 9 не дошло, последний этап показывает подсистему остановки.

Облако 3.208 менять не требуется; память, веса, словари и настройки не сбрасываются. Не прошивайте отдельные нейронные платы ради этого исправления.

## Проверки и ограничения

32 теста приложения прошли. Проверка исполняет настоящий фрагмент запуска C++ с подменой RouterBridge, без сервиса Monitor: RPC и ранние уведомления регистрируются до периферии. Проверены отсутствие инициализации PWM при старте, веб-маршруты, поиск, голосовая очередь и PCM-буфер. Это не полная сборка под Zephyr и не испытание на вашей UNO Q. Установить зависимости Arduino CLI для такой сборки в этой среде не удалось из-за сетевой ошибки загрузки; нельзя утверждать, что скетч физически прошит или проверен на оборудовании.
