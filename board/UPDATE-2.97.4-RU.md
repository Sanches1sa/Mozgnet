# 2.97.4 — скетч снова собирается: страж v2.97.3 снят

## Симптом

После установки 2.97.3 сборка скетча падает с ошибкой линковки:

```
sketch.ino.cpp.o: in function `n12BootGuardBody(void*, void*, void*)':
.../llext-edk/include/zephyr/include/zephyr/kernel.h:683:
undefined reference to `__aeabi_read_tp'
sketch.ino:3462: undefined reference to `z_tls_current'
collect2: error: ld returned 1 exit status
```

Скетч вообще не заливается на MCU, приложение вечно показывает
«мост: ждёт скетч». Никакие перезапуски (`app stop/start`, сторож,
bridge_doctor) помочь не могли: ошибка происходит ДО заливки.

## Причина

Страж запуска (новинка 2.97.3) работал на потоках Zephyr и в теле потока
вызывал `k_current_get()` (строка 3462). Ядро UNO Q (core 0.55.2) собирает
скетч как llext-модуль и **не экспортирует** для него TLS-символы
`z_tls_current` и `__aeabi_read_tp`. Линкер падает — скетча на MCU нет.

Важно: в сборке 2.97.3 неразрешёнными были ТОЛЬКО эти два символа — весь
остальной код скетча разрешился полностью. Поэтому после снятия стража
скетч собирается без других правок.

## Что сделано в 2.97.4

1. Страж запуска полностью снят (поток, `K_THREAD_STACK_DEFINE`,
   `k_thread_create`, `k_thread_abort`, `NVIC_SystemReset`), вместе с
   `#include <zephyr/kernel.h>`. `setup()` вернулся к проверенному порядку
   2.97.2: мост первым, шаги `on_boot` 1..9.
2. Подстраховку от зависшего `Bridge.begin()` делает Linux-сторож
   (`deploy_cli/neuro12_watchdog.sh`: `app stop` → рестарт
   `arduino-router` → `app start`) — он переживает и мёртвую службу Router,
   чего страж на MCU сделать не мог в принципе.
3. «Питоны» по-прежнему сняты (v2.97.3): мозг не пишет и не исполняет код
   Python; родные ядра (тензор, mozgnet) не тронуты. 32 теста проходят.
4. Версия скетча в `on_sver` — **2.97.4** (при шаге 1 и раз в 10 с),
   `APP_VERSION` Python — **2.97.4**. По диагностике сразу видно, что
   залился именно новый скетч.

## Установка

1. App Lab: приложение neuro_12 → **Stop** → **Build** → **Start**.
   Если сборка кэшировала старый объектник и ошибка повторяется — в
   терминале платы: `rm -rf /home/arduino/ArduinoApps/neuro_12/.cache`,
   затем снова Build/Start.
2. Либо полный ZIP 2.97.4 (импорт нового каталога, как и раньше, не
   переносит старую память — веса в EEPROM на плате).
3. Замена по одному файлу: достаточно заменить `sketch/sketch.ino` —
   остальное в 2.97.4 не менялось (в Python сменилась только версия).

## Проверка после запуска

- В журнале Python: «СКЕТЧ запуск: шаг 1 — мост поднят», затем шаги 2, 3, 4, 9.
- В диагностике (`/api/alive`, чип моста) версия скетча — **2.97.4**.
  Если видна 2.97.3/2.97.2 — новый MCU-код не загружен (см. п. 1 установки).
- Чип «мост» должен погасить «ждёт скетч» в течение первых секунд после
  шага 1.
