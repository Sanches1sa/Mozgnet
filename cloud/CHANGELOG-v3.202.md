# v3.202.0 — встроенный МАКС получает ИИ-ответ через общий API облака

## Что исправлено

Раньше облачный чат использовал dialog.respond, HTTP API напрямую вызывал brain.think, а встроенный МАКС мог подменить ответ результатом из чатов-источников и добавить инструкции после ответа. Поэтому настройка «тот же мозг» не обеспечивала одинаковый путь обработки.

Теперь общий сервис aiapi.cloud_reply используется облачным чатом в режимах «Авто/Облако», HTTP API /api/v1/ask в режиме cloud/auto и встроенным МАКС. Бот вызывает aiapi.answer и получает готовые JSON-поля answer/parts/zone/engine/sources; дальше передаёт parts на отправку. В сервис передаются вопрос, последние сообщения нужного чата, имя и идентификатор сессии.

Отдельные подстановки ответов из чатов-источников и дописывание инструкций после общего сервиса исключены. Сам индекс источников и прочитанные данные не удаляются, но больше не обходят общий облачный движок. При ошибке сервиса бот сообщает, что облако не ответило; скрытого перехода на другой движок нет.

Встроенный бот работает в том же процессе, поэтому используется внутренний API приложения, без HTTP-запроса сервера к самому себе. Вводить ключ приложения, адрес собственного компьютера или менять токен МАКС для этого не нужно. Существующий токен МАКС продолжает обслуживать получение и отправку сообщений. В статусе бота видны ai_engine=cloud-dialog, ai_transport=internal-api, ai_mode=cloud.

## Команды и заявки

Обработчик локальных команд _cmd по-прежнему вызывается до ИИ. Если он обработал сообщение, ответ уходит от него, обращение к ИИ не выполняется. Документы и вложения продолжают проходить прежнюю обработку. Сессии чатов разделены; текущий вопрос не дублируется в контексте.

Это изменение транспорта и общего сервиса ИИ, а не подключение к новой системе заявок. В переданном проекте не найден самостоятельный адаптер создания заявок во внешней системе; для такого адаптера потребуются её API и правила. Текстовый ответ ИИ сам по себе не является подтверждением регистрации заявки.

## Сходство ответа с облаком

Используются одни настройки, один путь проверки/поиска и тот же шаблон облачного ответа. Шаблон МАКС для локальных команд сохраняется; для ИИ применяется общий путь облачного чата. Приветствие может отличаться именем, история — контекстом конкретного чата. Генерация LLM случайна, поэтому независимые запросы не гарантируют побайтово одинаковый текст даже при одном движке. Изменения шрифта команд, формул и деление длинного сообщения по лимиту МАКС остаются транспортным оформлением, а не новым ответом.

Режим «Разговор» веб-панели по-прежнему отдельный (talkmind). HTTP API mode=talk теперь использует этот же путь вместо старого agent.talk. Встроенный МАКС подключён к режиму cloud, как вкладка «Облако/Авто», а не к свободному режиму «Разговор».

## Установка

1. Сделайте резервную копию приложения и data.
2. Установите ZIP через штатное обновление либо остановите облако и распакуйте поверх neuro12-cloud.
3. Перезапустите облако и отдельный процесс МАКС, если он был запущен отдельно. Обновите страницу без кэша.
4. В настройках МАКС проверьте пояснение о сервисе cloud-dialog. Сравнивайте ответ с облачным режимом «Облако/Авто» при одинаковом вопросе и сопоставимом контексте.

Ключи, данные, веса LLM, OCR, базы изображений, настройки Loop Transformer и прошивка платы не меняются.

## API для отдельного приложения

HTTP API остаётся защищённым ключом, который создаётся в настройках «API и ответы». Токен МАКС для него не подходит. Пример тела POST /api/v1/ask:

```json
{"question":"Вопрос пользователя","mode":"cloud","session":"max:12345","template":true,"name":"Алекс"}
```

Заголовок: Authorization: Bearer <ключ API приложения>. Возвращаются answer, parts, zone, engine=cloud-dialog и sources. Каждому чату нужен отдельный session. Для встроенного МАКС этот внешний HTTP-шаг не требуется — подключение выполнено в коде.

## Проверка

6 новых тестов: делегирование общему сервису, раздельные сессии и один экземпляр вопроса в контексте, отправка готовых parts без добавлений, честная ошибка вместо другого ИИ, приоритет локальной команды, общий talkmind для режима talk. Полный HTTP-тест подтвердил отказ 401 без ключа и совпадение ответа авторизованного API, веб-панели и готовых сообщений МАКС при детерминированной подмене генератора. Настоящие сообщения в МАКС не отправлялись. Реальное подключение к системе заявок не тестировалось. Также проверены регрессии фокуса ответа, общего поиска, МАКС и Yandex API.
