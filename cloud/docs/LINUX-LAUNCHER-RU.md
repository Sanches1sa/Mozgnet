# Ubuntu Server + Arduino UNO Q: Linux-лаунчер 3.205

Серверу не нужен графический рабочий стол. Этот лаунчер запускается на Ubuntu Server, управляет облаком и USB-подключённой UNO Q, а интерфейс открывается в браузере другого компьютера через SSH. На Ubuntu Desktop можно открыть тот же интерфейс локально. Исходники нового лаунчера: `launcher/neuro12-linux.py` и `launcher/linux/`. Прежние бинарные лаунчеры Windows/Linux сохранены и не пересобирались.

## 1. Подготовить Ubuntu

Распакуйте облако в каталог обычного пользователя, например `~/neuro12-cloud`. Установите зависимости:

```bash
sudo apt update
sudo apt install python3 python3-numpy python3-pil adb android-sdk-platform-tools-common openssh-server unzip
```

NumPy нужен для основной собственной LLM; Pillow — для работы с изображениями. OCR при необходимости:

```bash
sudo apt install tesseract-ocr tesseract-ocr-rus tesseract-ocr-eng python3-pytesseract
```

Для новой установки один раз подготовьте пароль панели и токен платы штатным установщиком, без отдельной системной службы:

```bash
cd ~/neuro12-cloud
bash install.sh --no-systemd --no-start --yes
```

Сохраните показанные пароль панели и токен. Для уже установленного облака с данными сохраняйте существующий `data/`, не заменяйте его пустой папкой. При переносе с Windows остановите старое облако и перенесите каталог данных целиком, включая обученные веса, а не только программу.

## 2. Запустить лаунчер

```bash
cd ~/neuro12-cloud
python3 launcher/neuro12-linux.py --check
bash launcher/linux-start.sh --start-cloud
```

Появится ссылка вида `http://127.0.0.1:8076/#token=СЛУЧАЙНЫЙ_ТОКЕН`. Это отдельный ключ лаунчера, он не совпадает с токеном платы или паролем облака. Ключ меняется при перезапуске. При локальном графическом рабочем столе можно добавить `--open`, чтобы открыть браузер.

На другом компьютере откройте терминал и создайте туннель (команда работает также в PowerShell с установленным OpenSSH):

```bash
ssh -N -L 8076:127.0.0.1:8076 -L 8077:127.0.0.1:8077 -L 7000:127.0.0.1:7000 USER@IP_UBUNTU
```

Замените USER и IP_UBUNTU. Оставьте эту команду работать. В браузере этого компьютера откройте ссылку лаунчера с его токеном. Три проброса нужны соответственно для лаунчера, облака и веб-интерфейса платы. При изменении портов меняйте их также в SSH-команде.

Панель слушает только loopback сервера, имеет проверку токена, Host и Origin. Входящий порт лаунчера не нужно открывать в интернете. Ошибки USB, импорта и запуска показываются в журнале; они не заменяются сообщением об успехе.

Если облако уже отвечает от внешней службы, второй процесс не запускается. Кнопка остановки останавливает только процесс, созданный этим лаунчером. Старой системной службой управляют отдельно: `sudo systemctl stop neuro12-cloud` / `start` / `status`. Не запускайте параллельно две копии на одном каталоге данных.

## 3. UNO Q по USB

Подключите UNO Q к Ubuntu Server USB-кабелем с передачей данных. Первичная настройка платы должна быть завершена; если ADB сообщает `unauthorized`, `offline` или `no permissions`, сначала устраните это состояние. Лаунчер не отключает USB-авторизацию и не запускает ADB от root.

1. Нажмите «Найти UNO Q по USB». В журнале появится вывод `adb devices -l`.
2. Скопируйте серийный номер (первый столбец строки со статусом `device`) в поле серийного номера. Сохраните настройки. Если плат несколько, выбор обязателен.
3. «Проверить плату» проверяет доступную оболочку и Arduino App CLI на ней.
4. «Список приложений» показывает приложения. Укажите точный ID нужного приложения, например `user:neuro_12`.
5. Нажмите «Запустить приложение». Сборку Linux- и MCU-частей выполняет установленный на UNO Q Arduino App CLI; облако не подменяет прошивку готовыми заглушками.
6. «Запускать при включении платы» задаёт это приложение как default средствами CLI.
7. «Подключить интерфейс платы» создаёт `adb forward` с локального порта Ubuntu 7000 на порт 7000 платы. После этого «Открыть плату» работает через третий SSH-проброс.

Если приложение ещё не установлено, раскройте «Установить приложение из ZIP» и выберите **свой исходный архив neuro_12 для App Lab**, содержащий `app.yaml`. Новый облачный ZIP не включает проект платы. Лаунчер проверяет ZIP, отправляет его на UNO Q через `adb push` и вызывает `arduino-app-cli app import`. Затем откройте список приложений и выберите импортированный ID. Импорт и запуск — отдельные действия. При совпадении имени CLI может отказать; лаунчер не удаляет прежнее приложение или его память принудительно.

Подготовка контейнеров/пакетов при первом запуске приложения может требовать интернета на самой UNO Q, даже если облако работает локально. Возможности команд зависят от установленной версии Arduino App CLI; вывод ошибок доступен в журнале. Физической платы в тестовой среде не было: построение команд и загрузка проверены с заглушкой ADB.

Официальные источники: [оболочка UNO Q через SSH/ADB](https://docs.arduino.cc/tutorials/uno-q/ssh/), [управление приложениями Arduino App CLI](https://docs.arduino.cc/software/app-lab/cli/cli), [исходный код CLI](https://github.com/arduino/arduino-app-cli).

## 4. Связать мозг с облаком

Открытый в браузере интерфейс платы и исходящие запросы приложения платы к облаку — разные соединения.

Рекомендуемый вариант: Ubuntu и UNO Q находятся в общей сети. В настройках neuro_12 укажите:

- `cloud_url`: `http://IP_UBUNTU:8077` (адрес, доступный самой плате);
- токен: содержимое `data/token.txt` облака;
- включите обмен с платформой/мозг-почту по существующим настройкам приложения.

Если серверный файрвол включён, доступ к 8077 разрешают для сети платы. `127.0.0.1` браузера пользователя не является IP сервера для самой платы.

Для USB есть отдельная кнопка «Создать USB reverse» (`adb reverse tcp:8077 tcp:8077`). Она делает хостовый облачный порт доступным через loopback UNO Q. Но приложение App Lab может работать в отдельной контейнерной сети: loopback контейнера не всегда является loopback платы. Поэтому reverse не меняет cloud_url автоматически и не выдаётся за гарантированное сопряжение. Проверьте запрос к облаку из среды приложения; при недоступности используйте сетевой адрес Ubuntu. Пробросы USB нужно восстанавливать после отключения/перезагрузки; кнопки доступны в лаунчере. Они не перезаписывают чужие сопоставления портов.

## 5. Автозапуск Ubuntu Server

После проверки остановите ручной лаунчер через Ctrl+C. От обычного пользователя:

```bash
cd ~/neuro12-cloud
bash launcher/install-linux-launcher.sh
sudo loginctl enable-linger "$USER"
```

Создаётся пользовательская служба `neuro12-launcher.service`, запускающая лаунчер и облако. `enable-linger` позволяет ей работать после выхода пользователя и стартовать без GUI при загрузке сервера. USB-доступ должен быть разрешён этому же пользователю.

```bash
systemctl --user status neuro12-launcher
journalctl --user -u neuro12-launcher -n 30 --no-pager
systemctl --user restart neuro12-launcher
systemctl --user stop neuro12-launcher
```

Ссылку с актуальным ключом лаунчера можно найти в журнале. Autostart приложения UNO Q задаётся отдельной кнопкой и относится к включению самой платы; он не устанавливает автопроброс USB после перезапуска Ubuntu.

## Нужен ли полноценный GUI Ubuntu?

Он необязателен. Если нужны монитор, мышь и рабочий стол на самом сервере, на Ubuntu можно установить `ubuntu-desktop-minimal` и после перезагрузки работать локально. Это расходует дополнительную память, которая могла бы использоваться LLM. Удалённый полноценный рабочий стол через RDP настраивается отдельно; данный лаунчер использует обычный браузер и SSH, без обязательной установки Xorg, GNOME, Xfce или xrdp.

## Обновление 3.206

Исправления технических ответов общие для Ubuntu и Windows: MAX, API и панель используют одинаковые проверки. Linux-лаунчер теперь отдельно показывает запуск процесса, инициализацию и готовность сервера. Обновляйте весь код облака из архива, а не только файлы launcher/, чтобы исправление ответов применилось к боту. Папку data сохраняйте.
