# Приложение UNO Q 2.97 / облако 3.208 — совместимость и русская речь

## Что проверено

Номера разных продуктов не должны совпадать. Пара 2.97.0 + 3.208.0 использует прежние маршруты /api/link и новые полные снимки 12 нейронов с session/seq. Контракт снимка проверен программно. Корневой скетч сообщает 2.97.0, Python APP_VERSION — 2.97.0. В облаке VERSION — 3.208.0. Это версии подготовленных файлов, а не измеренные версии вашего работающего оборудования.

| Приложение / облако | Совместимость |
|---|---|
| 2.97 / 3.208 | Рекомендуемая пара: нейронный контекст, длинный текст, строгий русский TTS |
| 2.96 / 3.208 | Старые API сохранены, но новый вывод PCM на D9 требует обновления приложения и скетча |
| 2.97 / 3.207 | Нейронный контекст работает; /api/tts/ru ещё нет. Голос доступен только при локальном eSpeak NG |

Прошивки отдельных нейронных плат из предыдущего обновления сохраняются. MCU хаба и Python нужно обновлять вместе: один только Python не добавит pcm_* RPC. Пины D4 и D6 не переназначены.

## Вывод русской речи на D9

D9 свободен в приложенном скетче: PB8, TIM4_CH3. D10/D11 уже заняты микрофонами; D6 — нейронным каналом. Частота TIM3, обслуживающего D6, не меняется. D8 остаётся прежним сигналом мотивации/нотами, а не разборчивой русской речью.

Синтезируется русский WAV на Linux-части UNO Q (eSpeak NG) либо в облаке (/api/tts/ru, без замены на тоны). Python фильтрует и переводит звук в моно PCM 8 кГц/8 бит. Через Bridge передаются блоки до 512 отсчётов с подтверждением порядка и свободного места. MCU имеет кольцевой буфер 32768 отсчётов, стартовый запас 8192 и аппаратный такт 8 кГц через TIM16/counter_servo. PWM D9 имеет несущую около 31.25 кГц. Звук воспроизводится отсчётами, не извлечением частоты из окна WAV.

**TIM16 резервируется под речь: не используйте одновременно Arduino_HardwareServo или другой драйвер, владеющий counter_servo.** D10 можно использовать как нынешний цифровой вход, но не как второй PWM TIM4 с другой частотой. Режим включён в настройках по умолчанию; выбор «Аудиоустройство Linux / USB» обходит PWM.

Подключение только при выключенном питании:

`D9 → резистор 1 кОм → узел фильтра → вход аудиоусилителя → динамик`

`узел фильтра → конденсатор 47 нФ → GND`

Земли платы и усилителя объединить. Используйте усилитель с аналоговым входом, совместимым с логикой/сигналом 3.3 В, входной развязкой и регулировкой громкости. При необходимости добавьте разделительный конденсатор по схеме усилителя, чтобы убрать постоянную составляющую. Указанный RC — простой начальный фильтр (~3.4 кГц), для лучшего подавления несущей нужен фильтр более высокого порядка. **Динамик 4–8 Ом напрямую к D9/GND подключать нельзя.** Пассивный пьезоизлучатель и прежняя схема ключа D8 не гарантируют качество речи; переноса одного провода без проверки усилителя недостаточно.

Драйвер использует Zephyr PWM/counter из ArduinoCore-zephyr. Если pwm4/counter_servo недоступны, частота таймера не подходит или устройство не готово, возвращается явная ошибка. При обрыве, переполнении, нарушении последовательности и отсутствии подтверждения текст не объявляется озвученным. Короткие провалы буфера учитываются счётчиком underruns; суммарно 1 с провалов останавливает поток. Длинные блокировки прерываний, программный UART VR3 и нагрузка Bridge могут ухудшить звук: это требуется измерить на вашей плате.

Это **экспериментальный вывод**: тесты передачи/буфера выполнены на компьютере, сборка под Zephyr и физический звук/таймеры UNO Q здесь не проверены. Не заявляется гарантированное качество. Внешние сервоприводы и усилитель не подключались.

## Установка

1. Сохраните память приложения и data облака. Остановите приложение/облако.
2. Импортируйте neuro12-app-v2_97_0.zip в App Lab. Обновятся Python и корневой sketch/sketch.ino с pcm_* RPC. При новом каталоге восстановите свою память отдельно; код не содержит ваших весов и данных.
3. Распакуйте обновление облака 3.208 поверх программы, сохранив data. На Ubuntu используйте Linux-архив и существующий Linux-лаунчер либо systemd-службу. Linux-лаунчер сохранён.
4. Установите eSpeak NG **в среде, где исполняется python/main.py**, или на сервере облака. В папке приложения выполните:

```sh
bash deploy_cli/install_russian_voice.sh --install
bash deploy_cli/install_russian_voice.sh --check
```

На сервере облака тот же скрипт находится в launcher/install-russian-voice.sh. Установка пакетов на хосте не устанавливает их автоматически внутрь контейнера App Lab. Если eSpeak отсутствует в контейнере, можно использовать установленный на облаке движок. Через облачный API голос синтезируется по сети; локальный eSpeak работает без сети. Поддерживается русский eSpeak NG, не загружается большая голосовая нейромодель.
5. В приложении откройте настройки: «Выход русской речи → PWM D9». Укажите адрес облака и токен, если синтез будет облачным. Включите TTS. Начните с короткой фразы и малой громкости усилителя. В статусе доступны ошибка и счётчик провалов. Для ALSA/USB выберите второй выход; контейнеру нужен доступ к /dev/snd. Скрипт --test проверяет только ALSA, не PWM D9.

Физическая прошивка/установка пакетов на вашей плате отсюда не выполнялась. При ошибке D9 проверьте версию MCU 2.97.0, наличие pcm_* RPC и ArduinoCore-zephyr; не переключайте D6 на голос.

## Длина ответа

Максимум генерации за проход увеличен с 10 до 42 слов. Bridge собирает несколько разных предложений из максимум шести свежих нейронных контекстов, ориентир — 1600 символов, предел — 3800. В чате, памяти и очереди речи снята прежняя обрезка 180–220 символов. В облаке увеличены соответствующие лимиты мыслей. Озвучка идёт частями последовательно; она не запускает несколько голосов одновременно.

Если сеть дала только одно пригодное предложение, оно останется коротким. Повторами и случайными словами длина не добирается. Пунктуация и шесть попыток не гарантируют смысл или правильность: это не обучение модели само по себе. Свои неподтверждённые мысли не используются как положительные примеры в локальном mn_feed.
