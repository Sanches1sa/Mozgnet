# CHANGELOG v3.194.0 — облако снова ходит в интернет

## Жалоба владельца

«Облако и чат-бот не ходят в интернет, пишет, что страница выдачи не
ответила». Проверено живой сетью на машине разработки:

- **Поиск Mail.ru (go.mail.ru) закрыл анонимную выдачу**: `go.mail.ru/search`
  отвечает 301 → `mail.ru/search` → 302 на `login.vk.ru` / `account.mail.ru`
  (требуется вход). Движок на каждый вопрос тратил секунды и давал 0 ссылок;
  журнал честно писал «выдача без ссылок», но в чат это не доходило.
- **Mojeek не отвечал** (TCP-таймаут) — второй поисковик молчал 9 секунд
  и тоже давал 0 ссылок.
- **Безключевая выдача Яндекса** (`yandex_html`, парсер с v3.155) была в коде,
  но в список движков не входила: v3.167 оставила Яндекс только по ключу API.
- Когда не отвечали и страницы, чат показывал безликую фразу
  «страницы выдачи не ответили» (`multisource.pages_answer`) без причин.

## Изменения

- **Поисковики: `yandex-html`, `mailru`, `mojeek`** (+ Google/Яндекс по
  ключу API; Википедия и Рувики — гарантированный источник). Выдача Яндекса
  — первая: на домашнем IP в России HTML-выдача обычно проходит без капчи;
  капча с датацентров ловится и фиксируется честной причиной. Настройка
  `web_engines` прежняя; старым сохранённым спискам «mailru,mojeek» выдача
  Яндекса добавляется первой автоматически.
- **Предохранитель движков** (`webfetch._engine_alive`, `_engine_note`):
  3 неудачи подряд — движок пропускается 10 минут (`skip_until`), успех
  сбрасывает счётчик. `top_pages` и `engine_search` не опрашивают движки
  на паузе. Поисковик, умерший за городом/в сети, больше не тормозит
  каждый вопрос.
- **Детект закрытия Mail.ru**: перенаправление на вход
  (`login.*`, `account.mail.ru`, `act=autologin`, `errorCode=`) даёт
  причину «требует входа (поиск без аккаунта закрыт)» и не повторяется
  вслепую (предохранитель).
- **Честный диагноз в чат** (`multisource.pages_answer`): при пустой выдаче
  первая причина — «поисковики молчат: Яндекс (выдача) — …, Поиск Mail.ru — …»
  (`webfetch.engines_diag`, до 2 движков, коротко по границе слова), затем
  причины несработавших страниц и подсказка про ключи API в Настройках.
  Формулировки без «. »/«; » внутри — `brain._short_err` доносит фразу
  целиком.
- **Сеть**:
  - `_resolve_public`: IPv4-адреса первыми (на машинах без IPv6 попытки к
    IPv6 съедали таймаут); если системный DNS не дал ни одной A-записи
    (пусто, только IPv6, блокировка) — DoH добавляет A-записи;
  - запасной DoH расширен: после JSON-шлюзов (dns.google, cloudflare-dns.com)
    — **проводной RFC 8484** на dns.yandex.ru (работает в российских сетях,
    где JSON-шлюзы замедлены): `_dns_wire_q`, `_dns_skip_name`,
    `_dns_wire_ips` (сжатие имён поддержано, rcode проверяется);
  - **HTTPS_PROXY/https_proxy/ALL_PROXY** (с логином/паролем) — CONNECT-туннель
    до того же ip:443 (`_proxy_addr`, `_proxy_connect`); TLS не меняется:
    SNI + проверка сертификата по имени домена, SSRF-гарантии прежние
    (приватные адреса запрещены всегда). DoH через `urllib` ходит через
    прокси сам.
- **Панель**: проверка поисковиков (⚙ → «Проверить поисковики») щупает
  Яндекс-выдачу первой строкой; селект поисковиков — 4 варианта, включая
  «Яндекс (выдача), Поиск Mail.ru и Mojeek — всё без ключа»; пояснение
  про предохранитель и честные причины.
- `wiki_search` в `top_pages` даёт до 3 ссылок (было 2) — Википедия
  остаётся гарантированным источником, когда поисковики на паузе.

## Тесты

Новые `tests/test_net194.py` (24 шт., офлайн, сеть подменена):
- предохранитель: пауза после 3 неудач, сброс успехом, движок на паузе
  не вызывается ни `engine_search`, ни `top_pages`;
- выдача Яндекса в дефолтном наборе и первым в старых списках, ключевые
  движки добавляются как раньше, `top_pages` реально вызывает движок Яндекса;
- Mail.ru: детект перенаправления на вход, подпись причины в состоянии
  движка, заголовки диагноза («Яндекс (выдача)», «Поиск Mail.ru»);
- диагноз пустой выдачи: первая причина — «поисковики молчат: …», без
  «. »/«; » внутри; без данных — «не дали ссылок»;
- проводной DoH: форма запроса (флаги, QDCOUNT, метки), разбор A-записей
  с указателем сжатия и полным именем, rcode≠NOERROR и мусор → пусто,
  резервный путь уходит в dns.yandex.ru;
- порядок адресов: IPv4 первым; «только IPv6» — DoH добавляет A-запись;
- прокси: парсинг `HTTPS_PROXY` (хост/порт/логин-пароль), туннель
  отклоняется не-200, успешный CONNECT пропускается.

Весь набор: 185 тестов, 2 падения — прежние (talkmind, как в 3.188.0).
