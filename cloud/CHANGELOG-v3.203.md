# v3.203.0 — мини-приложение MAX и API для внешней платформы

Добавлено приложение `/max-app`: заявки по работе сервисов, чат с ИИ облака, свои обращения и данные удалённого Ассистента с кнопками копирования. Один сервер обслуживает и приложение, и API ИИ. В настройках появился раздел «Приложение поддержки»: основной адрес, токен проверки запуска MAX, ключ для другой платформы, назначение ключа специалиста и выключение встроенного получателя MAX при переносе бота наружу.

Заявки действительно сохраняются в облаке с номером REQ. Пока другая платформа не подтвердила свой номер через API, приложение честно показывает «Сохранена в облаке». Доступны API для чтения, создания и изменения статуса. Приложение проверяет подпись и срок запуска MAX; чужой пользователь или обычный ключ ИИ не получает доступ к чужой заявке и её паролю.

Пароль удалённой помощи не сохраняется в файл заявки и не передаётся ИИ: он доступен в оперативной памяти до 2 часов и теряется после перезапуска. Копирование — по явному нажатию. Это временные данные программы удалённой помощи, не данные подключения к облаку.

Для сервера другой платформы добавлены адаптеры Python и Node.js в integrations. ИИ отвечает через существующий общий cloud-dialog, по одному адресу облака, без второго polling-бота. Профиль поддержки при отсутствии решения предлагает уточнение или заявку вместо внутренней формулировки про неподтверждённую память. Он не выдумывает ответ и не объявляет заявку созданной без записи.

Полная инструкция подключения, API-контракт, ограничения и ссылки на документацию MAX: [docs/MAX-PLATFORM-APP.md](docs/MAX-PLATFORM-APP.md).

Установка: резервная копия приложения и data → ZIP обновления → перезапуск облака → «Приложение поддержки». Для реального мини-приложения нужен доступный HTTPS-адрес и привязка URL в кабинете MAX. Если тот же бот работает на другой платформе, встроенный получатель облака должен быть выключен. Без названия/API платформы её адаптер невозможно установить автоматически; подготовлен общий контракт и серверный код.

Проверены 12 новых модульных сценариев и полный мобильный HTTP/Chromium-путь. Реальная регистрация в MAX, отправка сообщений и подключение к неизвестной внешней системе не выполнялись. Веса своей LLM, OCR, Loop Transformer и прошивка neuro_12 не переобучаются и не заменяются.
