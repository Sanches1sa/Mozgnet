# v3.195.0 — исправление Yandex Cloud Search API

## Что было сломано

Поиск отправлял GET на старый `https://yandex.ru/search/xml` с `apikey` в строке URL. Он не использовал текущий REST API v2. При наличии ключа API стоял после анонимной HTML-выдачи с капчами. Поиск регистрировал ошибки под именем `yandex-api`, а предохранитель и чат читали имя `yandex`, поэтому диагностика и пауза не совпадали.

## Что изменено

- `POST https://searchapi.api.cloud.yandex.net/v2/web/search`.
- API-ключ — только в `Authorization: Api-Key …`, Folder ID — в JSON `folderId`.
- `query.searchType=SEARCH_TYPE_RU`, `query.queryText`, `groupSpec`, `responseFormat=FORMAT_XML` по официальной схеме.
- Декодирование JSON `rawData` из base64 и разбор XML с сохранением текста выделенных слов и XML-сущностей.
- Настроенный Яндекс API вызывается первым. Анонимная HTML-выдача Яндекса при полной конфигурации API исключается; другие выбранные поисковики остаются резервом.
- Единое имя `yandex` для поиска, ошибок и предохранителя. После изменения ключа/Folder ID старая пауза и кэш Яндекса сбрасываются.
- Успешный ответ без ссылок отличается от ошибки. Понятные причины для 400/401/403/404/429, ошибок сети, JSON/base64/XML.
- Отдельная кнопка **«Проверить Яндекс API»** использует текущие поля формы, не сохраняет их сама и не требует повторного ввода сохранённого маскированного ключа.
- Проверка TLS включена, поддерживаются стандартные HTTPS-прокси. Перенаправления запроса с API-ключом запрещены. Секреты удаляются из диагностических сообщений.

## Как установить и проверить

1. Остановить облако и сохранить резервную копию его каталога.
2. Распаковать обновление поверх каталога, сохраняя `data/`. ZIP содержит папку `neuro12-cloud/`.
3. Перезапустить и обновить браузер Ctrl+F5. Версия должна быть **3.195.0**.
4. В настройках «Общие» / «Интернет и знания» убедиться, что включены интернет и поиск по сайтам, указан именно **Folder ID каталога** и API-ключ сервисного аккаунта.
5. Нажать **«Проверить Яндекс API»**. После успешной проверки сохранить настройки, если поля менялись.

Текущая роль для сервисного аккаунта — **`search-api.webSearch.user` на нужном каталоге**. Для API-ключа требуется область **`yc.search-api.execute`**. Права на YandexGPT сами по себе не подтверждают права на Search API. Старую роль `search-api.executor` официальный источник помечает устаревшей (она может сохранять совместимость, но для новой настройки рекомендована актуальная роль).

401 означает проблему с ключом; 403 — с доступом/областью ключа/правами на каталог; 429 — квоту или частоту запросов. Если ошибка говорит о недоступности сервиса или оплате, нужно проверить соответствующую настройку Yandex Cloud. Изменение кода не выдаёт сервисному аккаунту права автоматически.

Сохранённые ключи, Folder ID и пользовательские данные не изменяются установкой. Архив не содержит `data/`, ключей или паролей.

## Проверки

13 новых тестов Search API и 24 существующих сетевых теста v3.194 прошли. Проверены контракт POST/заголовков/JSON, маска сохранённого ключа, ошибки и редактирование секретов, base64/XML, пустая выдача, приоритет API и сброс предохранителя. В Chromium проверены кнопка на настоящем локальном сервере, использование несохранённых полей, сохранность прежних настроек и показ ошибки 403. Ответы авторизованного API в автоматических тестах подменяются.

Реальный новый endpoint доступен по HTTPS и на запрос с поисковым телом без ключа вернул ожидаемый HTTP 401. Полноценный поиск с пользовательским ключом здесь не проверялся: в присланном пакете нет пользовательского `data/settings.json`. Ключ не нужно присылать в чат — итоговая проверка выполняется новой кнопкой на установленном облаке.

```sh
python -m unittest discover -s tests -p test_yandex_search.py -v
python -m unittest discover -s tests -p test_net194.py -v
node --check web/app.js
```
