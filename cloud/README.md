Остановите запущенное облако. Сохраните резервную копию его каталога, особенно `data/`. Распакуйте этот архив поверх каталога облака с заменой файлов. В панели должна отображаться версия 3.150.1.

## Что требуется собственной LLM

Сам генератор кода уже был в проекте, но не имел первого приоритета. Для него нужны NumPy и обученная модель с токенами кода (источники кода изучаются через существующий механизм GitHub). Своя генерация поддерживает Python. Чистый Python backend без NumPy код не генерирует. В приложенных архивах нет обученных весов и состояния пользовательского облака: исправление маршрутизации не делает необученную сеть обученной. Внешняя модель необязательна и используется после попытки своей.

> **v3.146.0 — тензорные сети: веса зависят от частот плат и дыхания мозга.** Код платы не менялся, своя LLM не тронута.
> - **Общий тензор модуляции (`tensormod`).** На входе 8 чисел, все уже приходят от плат:
>   - дыхание и его фаза;
>   - уровень частоты генераторов плат;
>   - частота × дыхание;
>   - разброс частот плат;
>   - воля мозга (активность зоны сети);
>   - постоянный вход.
>
>   У каждой сети своя постоянная матрица, на выходе — вектор множителей её весов: m = 1 ± 50 % × сила. Покой (нет плат и дыхания) — m ≈ 1.
> - **Сеть материалов стала тензорной.** У каждого слова вектор смысла (128 чисел): свой постоянный вектор плюс выученный контекст (соседние слова). У материала — сумма смыслов его слов и частотный канал (уровень сигнала плат, при котором он выучен). Поиск — одно умножение матрицы на вектор, смешанное с точным поиском. Статья без слов вопроса получает только долю α, поэтому точные совпадения остаются выше. От плат и дыхания зависят:
>   - шаг учёбы контекстов;
>   - доля смыслового поиска α;
>   - вес частотного канала;
>   - дальность разрядки активации.
>
>   Тензор хранится рядом с сетью (`mozgnet_state.json.tensor.npy`). При первом запуске он выучивается по сохранённым предложениям, это несколько секунд.

Профиль — 24 знаковые частоты (по строке) f = 2000·d·sin(2πt/T), фаза непрерывна. Знак — код строки: «−» = НИЗКИЙ ×4 после синхро (у «+» ×2) и обратный код точек; уровни не инвертируются, синхро строки теперь ВЫСОКИЙ ×5, заголовок кадра ВЫСОКИЙ ×10.   сообщений, выучено, повторов, документов, ошибок, время.
- **Уже выученное не заучивается повторно.** Двойная защита: md5-дедуп
  текстов (как в живой учёбе) + **водяной знак** `scan_done[chat_id]`
  — timestamp самого старого обработанного сообщения. Повторный запуск
  кнопки уходит ГЛУБЖЕ по истории, а не пережёвывает то же самое
  (страницы-прогулки по старому считаются отдельным лимитом). Прогресс
  пишется на диск при любом выходе — остановка/ошибка посередине не
  теряет выученное.
- **Честные остановы и отказы.** Кнопка «Остановить скан» прерывает
  мягко, между страницами; бюджет страниц с новыми сообщениями — до
  200 на чат (лимит времени — 15 минут); МАКС отвечает 403 (нет права
  читать чат) — панель советует назначить бота администратором; чат
  с ошибкой не валит скан остальных. Свои сообщения бота пропускаются,
  голые ссылки и смайлы — не статьи, команды и обращения к боту в
  память не попадают. Маршрут `/api/maxbot/scan` зарегистрирован и на
  GET, и на POST — «нет маршрута» исключено (урок v3.23).
- **Что нужно:** бот включён и с токеном; чаты собираются по событиям,
  так что для скана группы бот должен быть её **администратором** —

## Быстрый старт (Windows 10/11)

1. Распакуй пакет в любую папку.
2. Самый простой путь — **двойной клик по `neuro12-cloud.exe`**: лаунчер
   найдёт Python, тихо запустит облако и откроет панель в браузере.
   (Если Python ещё не установлен — exe подскажет; тогда запускай
   `install.bat`, он поставит Python через winget сам.)
3. Полная установка с интеграцией в Windows 11 — **двойной клик по
   `install.bat`** (права администратора не обязательны — понадобятся
   только для правила брандмауэра, установщик сам спросит).

Установщик найдёт Python 3.8+ (или предложит поставить через winget),
скопирует платформу в `%LOCALAPPDATA%\neuro12-cloud`, создаст токен платы и
**пароль веб-панели**, добавит автозапуск при входе в Windows, откроет порт
в брандмауэре, положит ярлык на рабочий стол и запустит облако скрытно
(без окна консоли). В конце покажет адрес, пароль и токен.

```bat
install.bat                           :: обычная установка (автозапуск, файрвол)
install.bat -NoAutostart -NoFirewall  :: без автозапуска и брандмауэра
install.bat -Dir C:\neuro12 -Port 8080 :: свой каталог и порт
install.bat -Password мойпароль        :: свой пароль панели (сменить)
```

Файлы управления в каталоге установки:

| Файл | Что делает |
|---|---|
| `neuro12-cloud.exe` | лаунчер: двойной клик — запустить облако и открыть панель |
| `start.bat` | запуск в видимом окне (для отладки) |
| `stop.bat` | остановить облако |
| `uninstall.bat` | убрать: автозапуск, файрвол, файлы (память спросит) |
| `panel.url` | открыть веб-панель |
| `cloud_bg.vbs` | скрытый запуск (pythonw), им же пользуется автозапуск |
| `data\log.txt` | журнал |
| `data\port.txt` | фактический порт облака (пишет сервер, читает exe) |

Интеграция в Windows 11: задача **«neuro12-cloud»** в Планировщике заданий
(запуск при входе пользователя), правило **«neuro12-cloud»** в брандмауэре
Windows (входящий TCP 8077), ярлык на рабочем столе.

## Подключение платы neuro_12

1. На плате открой веб-чат (`http://<плата>:7000`) → панель **«⚙ Настройки»**.
2. Впиши:
   - **облако (cloud_url)** = `http://<IP-сервера>:8077`
   - **токен** = токен из вывода install.sh (файл `data/token.txt`)
3. Включи переключатели «мозг-почта», «словари», «платформа».
4. Через минуту плата появится в **Настройки → Устройства** со статусом
   «в сети» — она регистрируется сама (`POST /api/brains/register`).

Дальше всё происходит само:

| Что делает плата | Что делает облако |
|---|---|
| выгружает память (`/api/memory/save`) | хранит бандл каждой платы, отдаёт на чистую плату (`/api/memory/load`) |
| синхронизирует словари (`/api/dict/*`) | держит **объединение** словарей (ru_top/ru_pos/extra) |
| читает статьи KB (`/api/kb/list`, `/api/kb/article/<id>`) | копит базу знаний: статьи владельца, файлы, Википедия, статьи мозга |
| присылает мысли (`/api/think`, `/api/chat/thought`) | показывает в лентах «Хроника» и «Мысли плат», скармливает своей сети |
| спрашивает интернет (`/api/web/fetch`) | ищет в Википедии (SSRF-защита) |
| проверяет свой код (`/api/sandbox/run`) | исполняет в изолированной песочнице |
| учит функции (`/api/skills`, `/api/skills/learned`) | ведёт реестр функций; публикует и самокод мозга |
| пишет/читает письма (`/api/brain/msg`, `/api/brain/inbox`, `/api/brain/answer`) | мозг-почта: платы общаются между собой и с чатом облака |
| озвучивает речь (`/api/tts`) | WAV всегда: espeak, если есть, иначе встроенный «нейроголос» |
| кадры камеры (`/api/vision/frame\|raw`, `/api/vision/buffer`) | стрим и буфер детекций на странице «Зрение» |
| учитель (`/api/llm/teach`: word_goal, verdict, advice) | встроенный учитель без LLM; внешний — только если включишь |
| задания генератору (`/api/gen/task`) | генератор пишет длинные тексты по своим материалам |

## Камера — только на плате (в облаке её нет)

С v3.5 у облака НЕТ своей камеры и НЕТ настроек COM-портов: модуль
serialcam и вкладка «Камера UART» удалены целиком. Облако не открывает
последовательные порты и ничем не занимает UART — плате больше не с кем
конфликтоваться за провод.

Камера работает так: она подключена к плате (или является её частью),
плата снимает и шлёт кадры в облако по сети — POST `/api/vision/frame`
(с распознаванием) или `/api/vision/raw` (просто в стрим). Кадры видно на
странице **«Зрение»** (и `/cam`), детекции лежат в `/api/vision/buffer` —
платы забирают их как обычно.

Если ESP32-CAM подключена по проводу (скетч `esp32cam_uart.ino`) — пусть
поток принимает хаб на плате UNO Q, как и было изначально: один читатель
на провод.

## Пароль веб-панели

- Веб-панель (чат, настройки, зрение) закрыта паролем. При первом открытии
  браузер покажет форму «создайте пароль»; установщики задают пароль сами и
  печатают его в конце.
- Сессия живёт 30 дней (cookie `n12sid`, HttpOnly/SameSite=Strict) и
  продлевается при входе. «Настройки → Безопасность»: смена пароля и «выйти
  на всех устройствах».
- Подбор замедлен: не более 8 неудач за 15 минут с одного адреса, задержка
  на неверной попытке, сравнение через `hmac.compare_digest`, хеш PBKDF2
  (SHA-256, 240 000 итераций, случайная соль) в `data/auth.json`.
- Сброс пароля: удали `data/auth.json` — при следующем входе форма
  предложит создать новый; либо `install.sh --reset-password` /
  `install.bat -ResetPassword`.
- API плат не трогает пароль: платы работают по **токену платы**
  (`X-Mozg-Token`) как раньше. Кадры «Зрения» и файлы плат открыты плате
  с валидным токеном и владельцу с сессией.

## Веб-интерфейс

- **Чат** в стиле ChatGPT: сайдбар с сессиями, поиск, переименование/удаление,

- **Маршрут ответа**: `Авто` (облако, а без ответа — живая плата), `Облако`,
  `Плата` (вопрос уходит живому мозгу по мозг-почте, ответ приходит в чат).
- **«длинно»** — развёрнутые тексты от сети материалов.
- **App Lab** — кнопка в сайдбаре: приложения из кирпичиков (см. раздел
  ниже): палитра, канва, запуск по шагам, примеры.
- **Хроника** — лента всех сообщений плат. **Зрение** — кадры камер.
- **Настройки** (модал, как у ChatGPT): Общие, Устройства (статусы, «проверить
  связь»), Облачная память (размер бандлов, «забыть всё»), База знаний
  (добавить статью / файл), Функции мозга (реестр, тест, удаление),
  Учитель (LLM), Голос, **Безопасность** (пароль, выход на всех устройствах),
  Журнал.
- Кнопка **«Выйти»** в сайдбаре; при истёкшей сессии любой запрос сам
  перебрасывает на страницу входа.
- Тёмная/светлая тема, мобильная версия.

## LLM-надстройка — только обучение

`POST /api/llm/ask` закрыт навсегда (410) — LLM не отвечает в чате ни при
каких настройках. Учительский канал `POST /api/llm/teach` принимает цели
`word_goal | verdict | advice` (выбор слова-цели диктанта, вердикт фразе,
совет-наставление) и работает в двух режимах:

1. **Встроенный учитель** (по умолчанию, без сети): вердикты по словарю
   реальных слов, слово-цель из словарей облака, советы по темам/ключам и KB.
2. **Внешний учитель** (Настройки → Учитель): любой OpenAI-совместимый URL
   (`http://host:8000/v1/chat/completions`, Яндекс-GPT через совместимый
   прокси и т. п.). Запросы уходят туда ТОЛЬКО с учительскими промптами;
   готовые ответы в чат не попадают — сеть платы применяет советы сама.

## Экскурсия учителя для платы (App Lab)

Новая плата (или плата, которая «умеет только думать») обучается всем
функциям платформы автоматически:

- запуск: в чате облака скажи **«проведи экскурс»**, или Настройки →
  «Учитель» → **«▶ Начать экскурс»** (там же пауза/сброс, интервал уроков
  и журнал);
- учитель шлёт **13 уроков** через мозг-почту — плата забирает их своим
  обычным опросом `/api/brain/inbox` (30 с), читает, возбуждает нейроны
  и отвечает; за ответами следит вердикт учителя, слабый ответ — урок
  повторится (до 2 раз);
- темы уроков: знакомство и пульс, мозг-почта, облачная память, буфер,
  база знаний, словари, функции и самокод, сеть материалов и генератор,
  Википедия, зрение, голос, учитель, App Lab (кирпичики);
- тексты уроков встроенные (LLM не нужен). Если внешний учитель включён —
  он переформулирует уроки живее; всё равно только обучение, чат это
  не затрагивает;
- прогресс: Настройки → «Учитель» (сколько уроков ушло, ответов, журнал);
  данные в `data/tour.json`.

## Порты: плата и облако не конфликтуют

- У платы neuro_12 свой сервер — по умолчанию порт **7000** (её чат в
  App Lab), его трогать не нужно.
- Облако по умолчанию слушает **8077**. Если порт занят (другой программой
  или вторым облаком) — сервер сам возьмёт первый свободный из
  8077–8087 и запишет фактический порт в `data/port.txt`.
- Установщик и `neuro12-cloud.exe` читают `port.txt` и открывают панель
  по фактическому адресу. В настройках платы (cloud_url) указывай адрес
  облака с фактическим портом: `http://<IP-компа с облаком>:8077`.

## Мост к плате (облако само подключается к мозгу)

Облако не только ждёт регистрации плат — оно САМО стучится к плате по
адресу из настроек (по умолчанию `http://127.0.0.1:7000`, менять не надо,
если плата живёт на том же компьютере):

- каждые 15 секунд мост опрашивает `GET /api/state` веб-хоста платы;
- во вкладке «Устройства» — живой статус: версия мозга, последняя мысль,
  нейроны онлайн, заметки в памяти, аптайм; если плата НЕ отвечает — там
  же подсказка, что запустить;
- кнопка «Написать плате» — вопрос уходит плате напрямую (POST /api/send):
  плата думает САМА, зонной сетью, без LLM, ответ приходит в панель;
- в чате маршрут «плата» работает и без мозг-почты: если зарегистрированных
  плат нет, вопрос уйдёт через мост;
- новые мысли платы (say) попадают в общую ленту «Мысли плат».

Адрес платы меняется там же во вкладке «Устройства» (поле «Адрес платы»);
мост можно выключить одной кнопкой.

## App Lab: приложения из кирпичиков

Лаборатория приложений в стиле Arduino App Lab — кнопка **«🧩 App Lab»** в
сайдбаре панели. Приложение собирается из кирпичиков без программирования:

- **Плата**: «Спросить плату» (мост к 127.0.0.1:7000 — плата думает сама,
  зонной сетью, без LLM), «Последняя мысль платы», «Состояние платы»,
  «Мысль в ленту плат».
- **Мозг**: «Подумать над вопросом» (полный ответ облака), «Статья по
  теме», «Свободная мысль», «Навык по фразе», «Запустить функцию».
- **Знания**: «Искать в базе знаний», «Википедия: выжимка», «Словарь».
- **Память**: «Запомнить заметку», «Что помню про…», «Последние заметки».
- **Логика**: «Положить в переменную», «Собрать текст» (шаблоны `{имя}`
  и `{last}`), «Если… то… иначе», «Подождать секунд».
- **Вывод**: «Показать результат», «Результат в память».

Как это работает: кирпичики выполняются сверху вниз; каждый кладёт свой
выход в `{last}` (и в переменную, если заполнил поле «Запомнить выход»);
следующий кирпичик подставляет эти значения в свои параметры. Приложение
сохраняется в `data/applab.json`, кнопка «▶ Запустить» исполняет его по
шагам и показывает журнал: статус, время и текст каждого кирпичика.
Кирпичики к плате честно сообщают «плата недоступна», не роняя приложение.
Готовые примеры создаются в один клик из списка — потом можно менять
параметры под себя. Всего 21 кирпичик; каталог отдаёт сервер
(`GET /api/applab/bricks`), поэтому новые кирпичики появятся в палитре сами.

## Если панель «недоступна» (браузер не открывает localhost)

1. **Проверь, что облако запущено**: в командной строке
   `netstat -ano | findstr :8077` (если порт менялся — смотри
   `%LOCALAPPDATA%\neuro12-cloud\data\port.txt`). Строка с `LISTENING` —
   сервер жив, обнови страницу. Ничего нет — сервер не запущен, п. 2.
2. **Запусти вручную**: двойной клик по ярлыку «neuro12-cloud» на рабочем
   столе или по `%LOCALAPPDATA%\neuro12-cloud\neuro12-cloud.exe`.
   Альтернатива с консолью (видно ошибки): `start.bat` в той же папке.
3. **Через 1–2 минуты всё равно пусто?** Открой `start.bat` из окна cmd
   и прочитай, что напишет. Частые причины: антивирус удалил pythonw
   (переустанови: `install.bat`), порт занят другой программой
   (запусти `set NEURO_PORT=8080 && start.bat`).
4. **С v3.4 облако поднимается само**: страж «neuro12-cloud-guard»
   в Планировщике Windows каждые 5 минут проверяет и перезапускает облако.
   Проверить: `schtasks /Query /TN "neuro12-cloud-guard"`. Если установить
   старую версию — просто переустанови поверх: `install.bat`.
5. **Панель открылась, но пишет «недоступна» ПЛАТА?** Это уже другой экран
   (вкладка «Устройства», мост): плата не отвечает на 7000 — запусти мозг
   (`python main.py` в папке платы), мост подключится сам в течение 15 с.

## Безопасность

- **Веб-панель закрыта паролем** (см. раздел «Пароль веб-панели» выше).
- Токен платы (`X-Mozg-Token`) обязателен для личных данных плат: память,
  словари, письма, мысли, буфер, учитель. Токен хранится в `data/token.txt`
  (600) и в панели не публикуется наружу.
- Веб-шлюз Википедии: только `*.wikipedia.org`/`*.wikimedia.org` по https,
  приватные адреса запрещены. Если DNS-резолвер компьютера отдаёт для
  Википедии приватную заглушку (фильтр провайдера/роутера), шлюз берёт
  настоящий адрес через DNS-over-HTTPS (dns.google → cloudflare-dns.com) и
  соединяется напрямую с SNI и проверкой сертификата; если не помогло —
  в чате появляется честная причина простоя, а не техническая ошибка.
- Универсальный загрузчик страниц (v3.14, «первые 10 страниц выдачи»):
  только https (http повышается до https), ТОЛЬКО публичные адреса —
  системный DNS проверяется, при DNS-блокировке адрес берётся через DoH;
  SNI + полная проверка сертификата по имени домена (подмена адреса
  невозможна); каждый редирект проходит ту же проверку (только https,
  до 3 переходов); лимиты: 400 КБ и 9 с на страницу, 30 с на выгрузку,
  до 3 попыток IP на домен. Приватные/заглушечные/loopback-адреса НЕ
  подключаются НИКОГДА — ни настройками, ни ссылками из выдачи их не
  обойти; «плохие» страницы честно перечисляются в конце ответа.
- Песочница кода: белый список модулей, запрет eval/exec/open/сети, отдельный
  процесс с таймаутом.
- Файлы плат хранятся изолированно по устройствам, пути защищены от выхода
  за `data/`.

## Отличия от mozg12-cloud

- Один процесс и **ноль зависимостей** вместо Flask + root-агента + Макс-бота —
  установщику нечему ломаться, ставится даже офлайн.
- Модульный код (14 файлов по ролям) вместо монолита на 5000+ строк.
- Чат **всегда** отвечает движком облака (как плата — зонами и сетью),
  живая плата подключается маршрутом, а не «как повезёт».
- LLM-слой переосмыслен: только учитель, встроенный учитель работает без LLM.
- Память плат, словари и KB — атомарные JSON-хранилища с историей.

* **Инструкция для своей LLM** (pyapps.LLM_GUIDE): статья «Инструкция для своей LLM: приложения App Lab», раздел в «Инструкция и API» и в docs/APP_LAB_PYTHON.md; общая инструкция ИИ рассказывает, как своя LLM участвует в программировании.
